## 🌍 Vision

Every year, millions of students and job seekers go through the placement process largely blind — relying on scattered forum posts, outdated PDFs, and word-of-mouth advice to understand what a company's hiring process actually looks like.

**Placed_Path** exists to change that.

Our long-term vision is to build **the world's largest, most trusted, community-driven knowledge base for placement preparation, interview experiences, and career guidance** — a single destination where every candidate, regardless of college tier, background, or resources, can access the same quality of insight that only "seniors" or well-connected networks used to have.

We believe that **knowledge shared is opportunity multiplied**. Every interview experience posted on Placed_Path becomes a stepping stone for someone else's success.

---

## ❗ Problem Statement

Despite placements being one of the most high-stakes events in a student's life, preparation today is broken:

| Problem | Impact |
|---|---|
| 🧩 **Scattered interview experiences** | Spread across random blogs, PDFs, and closed WhatsApp/Telegram groups |
| 🏚️ **No trusted central platform** | No single source of truth for company-wise hiring patterns |
| 🧭 **Lack of preparation guidance** | Students don't know *what* to prepare or *how* to prioritize |
| 🔁 **Repeated mistakes across batches** | Each new batch relearns the same lessons the hard way |
| 🕳️ **Limited transparency in hiring** | Rounds, difficulty, and expectations vary wildly and undocumented |

The result: talented candidates underperform not because they lack ability, but because they lack **access to the right information at the right time**.

---

## ✅ Our Solution

Placed_Path solves this by creating a **structured, searchable, and collaborative platform** where every candidate who goes through an interview process can give back by sharing their experience — and every candidate preparing can learn from it.

- 🧑‍🤝‍🧑 **Community-first** — real experiences from real candidates, not generic tips
- 🏢 **Company-organized** — structured by company, role, and round
- 🔍 **Searchable & filterable** — find exactly what you're preparing for
- 🔐 **Safe & anonymous options** — share honestly without fear of judgment
- 📈 **Continuously growing** — the platform gets smarter and richer with every contribution

Simply put: **candidates who've been there, help candidates who are going there.**

## ⚙️ Installation

### Prerequisites

- **Node.js** `v18+`
- **npm** `v9+` (or `pnpm` / `yarn`)
- **Git**

### Steps

```bash
# 1. Clone the repository
git clone https://github.com/your-username/Placed_Path.git

# 2. Navigate into the project directory
cd Placed_Path

# 3. Install dependencies
npm install

# 4. Start the development server
npm run dev
```

The app should now be running at **`http://localhost:5173`** 🎉

## 🏗️ Project Architecture

### Frontend Architecture

Placed_Path follows a **feature-based, modular architecture** designed for scalability and maintainability:

- **Component-Driven Development** — UI built from small, reusable, composable components (via `shadcn/ui`)
- **Feature Modules** — Business logic grouped by domain (`auth`, `experiences`, `resume`, etc.) rather than by file type
- **Server State Management** — `TanStack Query` handles caching, background refetching, and synchronization with the API
- **Type Safety** — End-to-end TypeScript coverage across components, hooks, and services
- **Utility-First Styling** — Tailwind CSS ensures consistent, maintainable design without style sprawl
- **Client-Side Routing** — `React Router` manages navigation with lazy-loaded route-level code splitting

## 🤝 Contributing

Contributions are what make the open-source community such an amazing place to learn, inspire, and create. Any contributions you make are **greatly appreciated**.

### How to Contribute

1. **Fork** the repository
2. **Clone** your fork: `git clone https://github.com/your-username/Placed_Path.git`
3. **Create a branch**: `git checkout -b feature/amazing-feature`
4. **Make your changes** and commit them: `git commit -m "feat: add amazing feature"`
5. **Push** to your branch: `git push origin feature/amazing-feature`
6. **Open a Pull Request** with a clear description of your changes

### Contribution Guidelines

- Keep pull requests focused and atomic — one feature/fix per PR
- Write clear, descriptive commit messages
- Ensure your code passes linting (`npm run lint`) before submitting
- Add comments for complex logic
- Update documentation when relevant
- Be respectful and constructive in discussions

## 📏 Code Standards

- **ESLint** — Enforced for consistent, error-free code
- **Prettier** — Automatic code formatting on save/commit
- **Clean Code Principles** — Readable, maintainable, self-documenting code
- **Component Structure** — Small, single-responsibility, reusable components
- **Git Commit Convention** — Following [Conventional Commits](https://www.conventionalcommits.org/):

```
feat:     A new feature
fix:      A bug fix
docs:     Documentation changes
style:    Formatting, missing semi-colons, etc.
refactor: Code change that neither fixes a bug nor adds a feature
test:     Adding or updating tests
chore:    Build process or auxiliary tool changes
```
